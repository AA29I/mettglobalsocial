# Validation and acceptance evidence

## Verified locally

- `npm test`: 14 passing checks (Node test runner; includes the parent API workflow test and its subtests).
- `npm run build`: TypeScript and Vite production build pass.
- `npm run test:e2e`: one Chromium workflow passes at 1440px desktop and 390px phone widths, with no uncaught page errors. It covers owner setup, company/account creation, caption and frame-cover override persistence after reload, an explicitly blocked queue item, separate company data, and a mobile Drive reference workflow. These are browser viewport tests, not physical iPhone/Android or native application tests.
- `npm audit --omit=dev --audit-level=high`: zero reported production dependency vulnerabilities at the time checked. This is not a complete security audit.
- API checks reject cross-company accounts, overrides and mutation paths; require login; reject hostile request origins; invalidate logout sessions; and verify persisted records after reopening the database.
- OAuth checks use simulated provider responses to verify PKCE for Google, encrypted stored credentials, one-time/expiring state, Drive account scoping, and absence of secret values in readiness responses.
- YouTube checks use simulated provider responses to verify account-specific metadata, source URL validation, a private initial upload, delayed scheduling until thumbnail preparation, durable session recovery after a lost final response, and no duplicate video upload on retry.

Screenshots generated by the browser test are stored in ignored `test-results/desktop-overview.png` and `test-results/mobile-library.png`. They contain test data only.

## Live acceptance procedure

Use test content and explicitly authorize the action before submitting it through the UI. Configure the exact HTTPS origin, database, encryption key and provider developer apps per DEPLOYMENT.md. Create Mett Global and a second company. Authorize two eligible YouTube channels, browse Drive, create a future post with separate per-account titles/captions and suitable custom thumbnail images, then prepare each destination. Keep the browser open until YouTube confirms the schedule. Close it afterward and inspect both actual releases, titles, descriptions and covers at the target time. Compare publication times against the selected timezone.

Repeat with an expired authorization, removed Drive access and an interrupted preparation request. Resume the stored job rather than creating a new upload. Inspect Studio for ambiguous or partially prepared private videos. Confirm there are no duplicate uploads and no change to the other company's content. Do not replace this procedure with mocked tests or UI screenshots.

This version is a tested development build with a YouTube integration implementation pending live acceptance, not a finished all-platform Metricool replacement.

## Database-free interface preview

A separate build flag (`VITE_PREVIEW_MODE=true`) selects explicit browser-only storage and bypasses authentication without asking for passwords. Vercel builds this marked interface preview by default unless `APP_MODE=production` is configured. It does not call the server API, store OAuth credentials, or simulate successful connections or publication. A dedicated Chromium test covers preview startup, account/draft creation, persistence after reload, company separation on a phone viewport, and asserts that zero `/api` requests occur. This provides UI review evidence only.
